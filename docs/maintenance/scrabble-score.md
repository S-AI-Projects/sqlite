## How the runner resolves paths
The exercise metadata lives in `exercises/practice/scrabble-score/.meta/config.json`:
```json
{ "files": { "solution": ["scrabble-score.sql"], "test": ["scrabble-score_test.sql"], "example": [".meta/example.sql"] } }
```
- All paths are **relative to the exercise directory** (`exercises/practice/scrabble-score`).
- The validator parses this `files` object, resolves each entry, and verifies the files exist **inside** the exercise directory.
- Absolute paths or any `..` components are rejected.

## Generated artifacts vs. source files

|------|---------------------|---------------------|
| `reference_output.json` | ✅ | Test runner output (`output.json`). |

| `.meta/example.sql` | ❌ | Reference implementation – copied into the temporary copy only. |
| `scrabble-score_test.sql` | ❌ | Test suite – executed, not modified.

## Reproducible command to run validation manually
```bash
python3 work/R08-T038/check.py
```
Running the script will:
1. Validate the metadata paths.
2. Create a clean copy under `work/R08-T038`.
3. Replace the learner solution with the reference implementation.
4. Execute the test suite with SQLite.
5. Verify all enabled tests pass.
6. Emit `reference_output.json` and `versions.txt` in the work directory.
7. Run three negative‑fixture checks to ensure the validator correctly rejects malformed metadata.
```
All evidence files are left under `work/R08-T038/` for review.
```
