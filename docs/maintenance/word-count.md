# Word-Count Exercise Maintenance

This document provides maintenance and test-generation documentation for the `exercises/practice/word-count` exercise in the SQLite track. It details the automated generation pipeline from upstream problem specifications to test fixtures, verifies file classifications and reproducibility, highlights three key anchor test cases, and supplies exact commands to regenerate fixtures and run validation suites.

## How the Tests Are Generated

Test generation follows the route: `exercises/practice/word-count/.meta/tests.toml` + upstream `problem-specifications` `exercises/word-count/canonical-data.json` -> `exercises/practice/word-count/.meta/template.data.j2` and `exercises/practice/word-count/.meta/template.create_test_table.j2` via `bin/generate_tests` -> `exercises/practice/word-count/data.csv` and `exercises/practice/word-count/create_test_table.sql`.

### File Classification
Based on repository inspection:
- **Generated Files**:
  - `exercises/practice/word-count/create_test_table.sql`: Generated from `exercises/practice/word-count/.meta/template.create_test_table.j2` using `bin/generate_tests`. Populates the `tests` table with test metadata, inputs, and expected JSON strings.
  - `exercises/practice/word-count/data.csv`: Generated from `exercises/practice/word-count/.meta/template.data.j2` using `bin/generate_tests`. Contains raw input sentences and placeholder result columns.
- **Hand-Maintained Files**:
  - `exercises/practice/word-count/.meta/config.json`: Verified repository file containing exercise metadata, author attribution, and tracked solution/test/example file paths.
  - `exercises/practice/word-count/.meta/tests.toml`: Verified repository file containing UUID mappings, descriptions, and `include` / `reimplements` synchronization tracking.
  - `exercises/practice/word-count/.meta/example.sql`: Verified repository reference solution that passes all test cases using SQLite string manipulation and JSON aggregation.
  - `exercises/practice/word-count/word-count.sql`: Verified repository learner stub containing schema comments and an unsolved placeholder.
  - `exercises/practice/word-count/create_fixture.sql`: not generated by `bin/generate_tests` (maintained in the repository). Verified repository setup script creating the `"word-count"` table and importing `exercises/practice/word-count/data.csv`.
  - `exercises/practice/word-count/word-count_test.sql`: not generated by `bin/generate_tests` (maintained in the repository). Verified repository test runner script executing student solutions against fixtures and exporting results to `output.json`.
  - `exercises/practice/word-count/.meta/template.create_test_table.j2` & `exercises/practice/word-count/.meta/template.data.j2`: Verified Jinja2 templates committed to the repository that drive `bin/generate_tests`.

## Reproduction Commands

To reproduce the generated test files, use a Python with `jinja2` installed and the pinned `problem-specifications` repository commit:

1. Clone `problem-specifications` and check out the verified commit (`84a96854db1bda581317164d3e6ac6aa01723182`):
   ```bash
   git clone https://github.com/exercism/problem-specifications /tmp/specs
   git -C /tmp/specs checkout 84a96854db1bda581317164d3e6ac6aa01723182
   ```

2. Set up a cache directory pointing to the specifications:
   ```bash
   mkdir -p /tmp/cache/exercism/configlet
   ln -s /tmp/specs /tmp/cache/exercism/configlet/problem-specifications
   ```

3. Run the generator script using a Python with `jinja2` installed:
   ```bash
   XDG_CACHE_HOME=/tmp/cache python3 bin/generate_tests --no-pull word-count
   ```
   Note that the generator overwrites `exercises/practice/word-count/create_test_table.sql` and `exercises/practice/word-count/data.csv` in place. After generating in a clean working tree matching the committed state, running `git diff --exit-code -- exercises/practice/word-count` should print nothing.

### Why 4185a902 is replaced by 4ff6c7d7

Case `4185a902-bdb0-4074-864c-f416e42a0f19` was replaced by `4ff6c7d7-fcfc-43ef-b8e7-34ff1837a2d3` per upstream `problem-specifications` issue 1977. As documented in the canonical `comments` field ("Added a word with multiple letters after apostrophe"), the replacement test case introduces a contraction with several letters following an apostrophe (`"you're"`), ensuring student solutions do not assume contractions are limited to single-letter suffixes such as `"don't"`.

## Findings

- **Reproducibility**: Generation is completely deterministic and reproducible. Independent generation runs produce byte-for-byte identical output files matching the committed `exercises/practice/word-count/create_test_table.sql` and `exercises/practice/word-count/data.csv`.
- **Timestamp Handling**: Although `bin/generate_tests` computes an ISO-8601 UTC timestamp in its `header` variable at lines 128–135, neither `exercises/practice/word-count/.meta/template.create_test_table.j2` nor `exercises/practice/word-count/.meta/template.data.j2` renders `{{ header }}`. Consequently, no timestamp is written to the output, and zero lines required normalization during comparison.
- **Case Counts**: In `exercises/practice/word-count/.meta/tests.toml`, 15 entries are listed: 14 included and 1 excluded (`include = false`). Separately, upstream `canonical-data.json` contains exactly 15 test cases that carry a UUID. Among the included entries in `exercises/practice/word-count/.meta/tests.toml`, 1 case (`4ff6c7d7-fcfc-43ef-b8e7-34ff1837a2d3`) reimplements the excluded case (`4185a902-bdb0-4074-864c-f416e42a0f19`), producing exactly 14 rendered SQL cases and 14 CSV records. All 14 tests pass with `exercises/practice/word-count/.meta/example.sql` and 0 pass with `exercises/practice/word-count/word-count.sql`.
- **Note on Issue #52**: GitHub issue #52 claimed that no per-exercise Jinja template exists for `word-count`. This claim is incorrect: both `exercises/practice/word-count/.meta/template.create_test_table.j2` and `exercises/practice/word-count/.meta/template.data.j2` exist and were committed in commit `3133f1d`. Furthermore, the issue description contained an unfilled `:1}` template placeholder rather than a complete list of named cases. The three anchor cases above were selected to provide full verification coverage for the `include`, `include = false`, `reimplements`, and quote-escaping logic in `bin/generate_tests`.
